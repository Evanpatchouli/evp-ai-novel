# evp-ai-novel

通用的本地小说创作工作台。

面向单一作者的本地小说工程控制台。它读取仓库中的 Markdown、YAML 与 Git 状态，帮助作者完成章节终稿验收；仓库文件仍是唯一权威数据源。

## 环境要求

- Windows 10/11
- Node.js 20.19 或更高版本（也支持 22.12 及更高版本）
- npm
- 正式版随应用提供 MinGit。源码开发和测试需要 PATH 中的 Git 2.28.0 或更高版本。

## 安装与启动

在工作台目录执行：

```powershell
npm install
npm run dev
```

开发模式会同时启动 Koa 本地服务与 Vite 前端。服务启动时会检查系统 Git 并在终端显示版本和访问地址。如果缺少 Git 或版本过旧，请安装或更新 Git，重新打开终端并用 `git --version` 检查。首次进入后点击“新建小说”，填写书名、作者及可选简介。工作台会在 `%APPDATA%\evp-ai-novel\novels` 下创建小说目录和本地 Git 仓库；顶部选择器可切换小说，重启后恢复上次选择。应用不选择或读取外部小说仓库。

生产构建与启动：

```powershell
npm run build
npm start
```

`npm run build` 按构建用 Node.js 的架构（x64、arm64 或 ia32）下载锁定的 Windows MinGit，校验 SHA-256 后将完整内容放入 `dist/vendor/mingit/`。已验证的 ZIP 缓存在 `output/mingit-cache/`，离线构建也可提前放入同名官方 ZIP。分发时保留整个 `dist/` 目录及应用的运行依赖。用户启动正式版时，建库、状态和版本历史都通过应用目录内的 `cmd/git.exe` 执行。启动检查发现内置 Git 缺失或版本不符时，会退出并提示修复发布包。

在目标架构的 Windows 上运行 `npm pack` 会先构建和自测，再生成包含 MinGit、许可声明、工作台源码与编译产物的 `.tgz` 发布包。解包后，在 `package/` 目录运行 `npm install --omit=dev` 安装 Node.js 运行依赖，再运行 `npm start`。

质量检查：

```powershell
npm run typecheck
npm test
npm run benchmark:stage2
npm run benchmark:stage6
npm run check
npm run format
```

`npm run format` 使用 Prettier 格式化工作台源码、测试、根级配置和本目录 Markdown；它会直接写入文件，建议在确认工作区改动后执行。

## 主要能力

- 汇总各卷章节状态、字数与当前任务；
- 章节总览按卷独立折叠，支持按状态、章号和标题筛选，并按仓库记忆展开状态；
- 提供卷详情与只读文档详情深链接；卷详情展示状态统计、首末章、当前任务、卷纲和关联记录；
- 章节详情默认使用安全 Markdown 阅读模式，并在页首、页尾提供跨卷连续的上一章、下一章与返回卷导航；阅读态可通过右下角快捷操作复制磁盘源 Markdown 的去空行版本，非 `final` 章节还可显式切换编辑/预览；
- 非 `final` 章节可在内存草稿中编辑 Markdown；切回预览会渲染未保存草稿并保留离开保护，`Ctrl/Cmd+S`、编辑器保存按钮和仅编辑态出现的“快捷保存”都只打开完整差异预览，逐项确认后才写入；
- 卷详情可在卷末新建章节，章 ID 按全书现存与归档历史最大编号递增，并同步更新卷状态表；
- 可从章节总览新建卷，从卷详情修改卷名；卷 ID 与卷号由服务端按现存及归档历史递增分配，卷名修改只更新 `状态.yaml`，不移动目录；
- 空卷可连同其拥有的规划目录移动到 `99_归档/工作台回收站/` 并恢复；预览会展示卷纲、生产、审稿和发布引用影响，非空卷或存在活动生产任务时拒绝归档；
- 章节可移动到 `99_归档/工作台回收站/`，回收站支持从 manifest 恢复正文与原状态。
- 顶栏小说选择器提供永久删除。卷和章节可从详情页预览并确认删除，已删除的卷号和章号会保留身份记录。
- 文档库提供按权威目录分级的 Markdown 树与全文搜索；通用 CRUD 只开放 `10_圣经/`、`20_规划/`、`70_素材/`，正文、生产、审稿、发布和归档资料由专用流程维护或保持只读；
- 受支持 Markdown 可在已有安全目录中创建、显式编辑、归档和恢复；详情返回内容哈希与逐操作 capabilities，外部修改、规范化等价路径和链接节点会拒绝写入；
- 可选 `00_项目/小说.yaml` 通过 `/novel` 结构化表单维护，缺失时返回兼容默认值但不隐式落盘，创建和更新均展示规范化 YAML 的完整差异；封面复用组件库文件选择器，仅接受不超过 5 MiB 的 PNG，确认后与 YAML 在同一可恢复 mutation 中创建或替换 `70_素材/封面.png`；
- 未保存草稿会阻止刷新、路由离开和仓库切换；外部文件变化会拒绝覆盖并保留当前草稿；
- 九阶段终稿验收完整接入章节详情；持久化状态表示最后完成的检查点，进度栏高亮下一项待操作步骤，内容区一次只展示当前步骤；页面优先继续当前章活动任务，`final` 章节需要作者显式允许后才能创建新一轮修订任务；
- 使用 Zod 校验卷状态 schema v2，诊断重复卷号或章 ID、状态范围重叠或空洞、章节数不一致、纯卷 ID 目录和 H1 异常；
- 卷目录固定使用不可变卷 ID；卷号、卷名和生命周期状态由 `状态.yaml` 的 `volume` 字段管理，修改卷名不移动目录；
- 仪表盘与 `/api/repository/health` 返回仓库健康报告，阻断问题不会被静默解释为普通状态；
- 卷章索引只返回摘要，章节正文通过详情接口延迟读取；摘要缓存根据文件大小、修改时间、状态变化和内容哈希安全失效；
- 使用 React Router 提供仪表盘、章节、工作流、文档、Git 与自动化独立页面，支持直达和刷新；
- 自动化能力页使用 `broswer.svg`、`upload.svg` 和 `read-data.svg` 区分打开浏览器、上传任务包与读取页面输出，并为窄屏提供紧凑横排；
- 通过 `@ldkj/web-ui` 主题能力统一界面，顶部栏使用组件库 `Select` 在“宣纸白”“深墨黑”“晴空蓝”之间切换；偏好保存在本地并同步组件库明暗令牌，业务选择器同样使用 `Select`，仪表盘使用 `Grid` 与 `Progress`；
- 使用工作台 `assets/favicon.png` 作为浏览器站点图标；
- 全局右下角使用组件库 `GhostButtonGroup` 提供刷新当前页面、回到顶部及页面按需注册的快捷操作；页面卸载后会自动清理其动作；
- 创建独立生产任务并保存输入快照；
- 生成供 ChatGPT Web 手工上传的上下文包与提示词；
- 任务包生成后可在成功提示中直接下载 ZIP 或打开所在文件夹；Windows 下会启动可见的文件资源管理器，并在进程成功启动后才报告成功；
- 实际打包的候选资料会写入任务元数据，刷新或重新进入任务时自动恢复勾选状态；旧任务可从 ZIP 清单只读恢复；
- 导入并保留审稿报告原文，辅助提取分级问题；
- 审查提示词要求依次完成正文内部、相邻章节、圣经设定、人物视角、结构体验及语言格式检查，通过证据复核、严重程度定义与提交前清单抑制提前收束和过度分析；输出继续使用固定 Markdown 报告结构，解析时以问题标题为边界聚合证据、影响和建议；
- 代办卡片安全渲染 Markdown，支持 GFM 列表、表格、代码和链接，但不执行原始 HTML；
- 审稿报告保存并解析成功后，通过组件库静态 Toast 明确反馈“解析成功”；
- 正式写入前可从进度栏回退到已完成阶段；失效的下游工件移入任务历史目录，不直接删除；
- 记录作者对每条问题的批准、部分批准、拒绝或稍后决定；
- 第五步优先生成 `04_AI修订精简包.zip`，只携带原稿、冻结的修订风格卡与当前卷上下文卡、相邻章节、所选专题资料、已采纳决策摘要和修订提示词；不支持 ZIP 上传的 DeepSeek 等平台可生成内容一致的 UTF-8 无 BOM `04_AI修订精简单文件.txt`；原 `04_AI修订上下文.zip` 保留为完整审计包，用于追溯与复杂复核。三种输出都复用第三步冻结字节，且只有全部问题完成决策后才允许生成；
- 决策备注使用可纵向调整的多行输入；本地草稿保证键入即时响应，向任务状态的同步使用 `es-toolkit` 节流，并在失焦或卸载前提交尾值；问题卡片按对象引用隔离渲染，修改一项不会重复渲染其他卡片的 Markdown；
- 九阶段向导在手机端将完整步骤轨压缩为当前步骤摘要，可按需展开；审稿与修订交接在桌面端使用等高双栏并自适应铺满视口剩余高度，内部长文本独立滚动，720px 以下恢复单栏自然高度；人工决策和终审提供稳定操作区，高严重度沿用组件语义实底并配白字，低严重度使用分级中性表面，长差异默认折叠未改正文并支持逐项跳转与完整上下文切换；
- 对比输入稿和修订稿，提示大段改写、标题变化及疑似新增设定；
- 经五项人工确认后预览正文与状态变更，再以短时效令牌提交；
- 第八步只读预览与第九步任务归档使用共享的响应式操作区；写入预览生成后以自适应摘要条展示正文目标、状态表和令牌有效期，危险提示与最终确认按钮保持独立操作间距；
- 正式提交通过可恢复 mutation 同时更新正文、状态 YAML、任务 YAML 与写入记录；预览令牌一次性使用，并绑定当前仓库、会话和预览时文件哈希；
- 阶段回退和任务归档同样通过可恢复 mutation；终稿 token 额外绑定任务身份，正文写入统一要求恰好一个 H1，归档任务可通过原深链接只读查看完成状态；
- 所有现有任务写入口共用仓库级互斥锁；启动和仓库切换会检查未完成事务，无法安全自动恢复时进入只读的 `recovery-required` 状态；
- 使用 Git 查看文件变化、保存本地版本及查看版本历史；变化文件列表使用共享 `ScrollArea`，最多展示 20 个标准行高，更多记录在容器内滚动且不会截断；
- 通过系统默认程序打开文件。

## 目录说明

```text
evp-ai-novel/
├── client/       React 界面与 Vite 配置
├── server/       Koa API、文件工作流及 Git 版本管理
├── shared/       前后端共享 TypeScript 契约
├── scripts/      构建、发布自测和性能基准脚本
├── third-party/  内置 MinGit 的组件许可记录与补充版权声明
├── tests/        Vitest 安全边界与工作流测试
├── package.json
└── README.md
```

前端按 `app/`（路由与仓库会话）、`features/`（业务页面）、`components/`（共享展示组件）和 `domain/`（领域规则）分层。卷、章节和文档详情分别使用 `/chapters/volumes/:volumeId`、`/chapters/volumes/:volumeId/chapters/:chapterId` 与 `/documents/view?path=...`；文档创建与小说元数据使用 `/documents/new`、`/novel`，卷创建页和改名页使用 `/chapters/volumes/new` 与 `/chapters/volumes/:volumeId/edit`，卷末新建页使用 `/chapters/volumes/:volumeId/chapters/new`，卷章文档回收站使用 `/archive`，工作流任务使用 `/workflow/:taskId`。仓库切换时会清空旧任务上下文并回到仪表盘。

运行时生产工件写入所选小说仓库的 `30_生产/active/`，正式正文仅在作者完成确认和写入预览后更新到 `40_正文/`。不要编辑仓库的 `build/` 生成文件。

## 安全边界

工作台遵守以下硬性约束：

- 不接入 OpenAI API，不保存 ChatGPT 登录信息，不读取浏览器 Cookie；
- 不自动上传仓库，任务包只包含作者预览并选择的文件；
- 创建任务和导入中间结果不得覆盖 `40_正文/`；
- 审稿解析失败也必须保留完整原始文本；
- 阶段只能向已完成的早期阶段回退，不能通过切换跳过审核门槛；已写入或已归档任务禁止回退；
- 未批准或标记“稍后决定”的问题不得进入修订要求；
- 人工终审稿必须先独立保存，随后五项作者确认必须全部为真，才可进入写入预览；终审保存、五项确认和正式写入不能在同一界面步骤中跳过；
- 正式写入必须经过预览，校验短时效令牌及写入前文件哈希，并保证正文和状态更新具有事务性；
- 本地写请求只接受回环 Host、受信任 Origin 和当前进程会话令牌；仓库切换会同时轮换请求令牌并作废旧写入预览；
- 所有仓库路径必须在仓库根目录内，拒绝 `..`、绝对路径、符号链接等路径逃逸；
- 章 ID 必须采用规范格式并在全书唯一；Markdown H1 是章节标题的唯一权威来源；
- `final` 章节禁止直接编辑；终稿归档需要额外明确确认，存在活动生产任务时所有章节归档都被阻断；
- 卷归档只允许空卷，且存在活动生产任务时阻断；不能通过卷级操作绕过章节终稿规则；
- 通用文档写入只允许安全的 Markdown 相对路径和明确开放的权威目录；章节正文、状态 YAML、生产任务、审稿证据、发布记录、归档内容及工具文件不能通过文档 API 绕过专用门禁；
- 归档和恢复必须先预览；恢复目标已占用、大小写或 Unicode 规范化冲突、manifest 损坏或归档哈希变化时拒绝覆盖；
- 未知高版本、无效状态范围或其他阻断级健康问题不得被写入流程绕过；
- 创建小说时初始化本地 Git 仓库；用户主动保存版本时执行 add 和 commit。不会自动提交、推送或修改 Git 配置；
- 自动化能力默认关闭，应用不会自动控制 ChatGPT Web。

如果写入预览后正文或状态文件被其他程序修改，原令牌应失效；请重新预览，不要绕过冲突检查。正文提升为 `final` 始终需要作者本人明确确认。

## 数据恢复

应用不使用专有数据库。退出工作台后，所有原始资产仍可用普通文本编辑器和 Git 直接读取。遇到异常时先检查 `30_生产/active/` 中的输入快照和任务记录，再使用 Git 查看正式文件差异。

运行中的锁、事务日志和恢复标记保存在所选仓库被 Git 忽略的 `.workbench/`。工作台启动及切换仓库时会自动回滚未完成事务，或清理已经提交的残留工件；若文件哈希、备份或日志无法证明可安全恢复，则保留现场并标记 `recovery-required`。此时章节、文档和健康报告仍可读取，但所有写操作会返回 `MUTATION_RECOVERY_REQUIRED`，不得手工删除标记后继续写入，应先核对日志、临时文件、备份文件与 Git 差异。

该机制提供普通文件系统上的可恢复多文件与目录树事务，不等同于数据库或断电场景下的持久化原子事务。关键单文件安装使用同目录原子替换，并在落盘前同步文件内容；目录树移动以内容感知快照、逐操作日志和启动恢复证明现场。当前不承诺父目录元数据在突然断电时已经同步。

## 许可证

工作台代码使用 [GNU GPL v3.0](LICENSE) 许可证。前端打入发布包的依赖及其许可原文列在 `dist/client/THIRD-PARTY-LICENSES.md`。内置 Git 使用 GPL v2，其他 MinGit 组件按各自的许可证分发。发布目录内的 `dist/vendor/mingit/THIRD-PARTY-NOTICES.txt` 列出了各组件的版本、上游许可证记录和声明文件的位置。原始声明及补充版权文本均可离线查阅。

升级 MinGit 时，从 [Git for Windows 官方发布页](https://github.com/git-for-windows/git/releases) 核对发布标签、各架构的 ZIP 文件名和 SHA-256。用 `Get-FileHash` 读取每个已验证 ZIP 中 `cmd/git.exe` 的 SHA-256，在目标 Windows 上从解压目录运行 `.\cmd\git.exe --version` 记录完整输出，再更新 [版本锁](server/mingit-lock.json)。例如本版官方 ia32 的实际版本带有 `.dirty` 后缀。

对照每个 ZIP 的 `etc/package-versions.txt` 和相同版本 Git for Windows SDK 包的 `desc` 文件，更新 [各架构许可记录及补充声明](third-party/mingit/)。打包会检查组件和版本是否全部有记录，并逐字节核对解压后的许可证与版权声明。在各目标 Windows 架构上运行 `npm run build`，构建会清空测试进程的 PATH，用产物实际创建小说、保存版本、读取状态与历史。

公开分发时，按各组件的条款随发布提供相应源码。可在 Git for Windows SDK 中运行上游的 [get-sources.sh](https://github.com/git-for-windows/build-extra/blob/main/get-sources.sh)，传入 `--mingit` 和该架构 `etc/package-versions.txt` 的绝对路径，收集对应版本的组件源码。
